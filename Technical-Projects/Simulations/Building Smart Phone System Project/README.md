# 📱 Smartphone Operational Requirements – Systems & Security Analysis

## 📌 Project Overview

This repository contains a **system-level Operational Requirements Document (ORD)** for a **Smartphone system**, developed as part of practical coursework during my **Master’s in Cybersecurity** program.

The document defines **functional, non-functional, and interface requirements** for a smartphone operating within real-world network environments, including **cellular, GPS, and Wi-Fi systems**. The focus is on **clear requirement specification, system behavior, performance constraints, and operational reliability**.

The requirements are written at the **system level**, emphasizing interactions between the smartphone and **external users, networks, and service providers** .



## 🎯 Objectives

* Define clear **input and output requirements** for a smartphone system
* Specify **external interfaces** with cellular, GPS, and Wi-Fi networks
* Capture **functional behavior** under normal and hostile conditions
* Establish **non-functional constraints** such as performance, cost, and availability
* Apply structured requirements engineering principles



## 🧠 Key Areas Covered

### 🔹 Functional Requirements

* User authentication and access control
* Call handling and call control workflows
* User interaction with apps, navigation, and system settings
* Provider and maintenance access functions
* System response to normal and hostile situations

### 🔹 Input / Output Requirements

* User inputs (passwords, commands, activities)
* Network inputs (cellular, GPS, provider systems)
* System outputs including status displays, prompts, and confirmations
* Control signals exchanged with external networks

### 🔹 External Interfaces

* **Cellular Network:** CDMA-based communication
* **GPS Network:** Navigation and location services
* **Wi-Fi:** IEEE 802.11 standards with backward compatibility



## ⚙️ Non-Functional Requirements

### 📊 Performance

* Power up/down within defined time limits
* Fast user and provider authentication
* Low call connection latency
* GPS satellite acquisition within strict thresholds

### 🔐 Availability & Reliability

* Mean Time Between Failures (MTBF) targets
* Mean Time To Restore (MTTR) goals
* System resilience and maintainability

### 💰 Cost Constraints

* Manufacturing cost limits per device
* Reduction in provider maintenance effort



## 🛡️ Cybersecurity Relevance

This project directly supports cybersecurity learning by addressing:

* **Access control and authentication requirements**
* **System availability and reliability**
* **Secure interaction with external networks**
* **Operational response to hostile situations**
* **Provider vs user privilege separation**

These requirements form the **foundation for secure system design, threat modeling, and risk assessment**.



## 📘 Methodology

* Interpreted system-level operational needs
* Structured requirements using formal “shall” statements
* Distinguished between **functional** and **non-functional** constraints
* Mapped system interactions with external entities
* Ensured clarity, traceability, and testability of requirements



## ✅ Key Takeaways

* Strong understanding of **systems requirements engineering**
* Ability to translate operational needs into structured specifications
* Awareness of performance, cost, and security trade-offs
* Foundation for secure system architecture and validation
